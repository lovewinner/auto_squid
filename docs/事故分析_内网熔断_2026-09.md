# 事故分析:内网目标走外部代理导致批量熔断 + 全站 502(2026-09-15)

> 本次会话诊断结论 + 白名单配置落地。根因不是 P0 逃生走廊失效,而是**内网目标走错路由路径**。
> 修复:10.14.25.86 进 `router.local_direct_domains` 白名单,走本机直连。

---

## 现象

`auto_squid.log` 在 **23:06:40 → 23:08:48** 刷屏 `ERROR:auto_squid.router:all proxies failed
for http request http://10.14.25.86:20128/...`,每 ~80–100ms 一对(`/` + `/favicon.ico`),
伴随 `client 59.67.225.91 header timed out after 30s`(浏览器排队请求被 3s 悬住,30s 断链)。
web 面板请求 10.14.25.86 的每个子资源都打 ERROR。

> 先排除了一个假象:23:07:32-44 的"空 ERROR 段"并非无 attempt 日志,而是日志切片抽样误差。
> 逐行核对,每次 escape 竞速失败其实都伴随 `upstream attempt FAILED pid=local`(见下)。

## 根因链(三段)

### 1) 灾难点火:内网目标经外部代理即时失败 → 5 个外部代理批量熔断(23:06:40-46)

10.14.25.86 是**本机/内网可达**的服务(实测本机 TCP 0ms 直连通),但**不在白名单**。请求走了代理路径:

- 5 个外部代理从远端连不上该内网 IP → **~5ms 级即时失败**(connect refused / 路由黑洞)。
- `consec_fail` 快速攒满 → 逐个 `circuit opened`(backoff 64s → 128s 指数),日志见 23:06:43-46
  一排 `circuit opened for proxy 219-116 / 239-101 / 25-88 / 239-192 / 247-246`。

### 2) local 也被卷入熔断(23:07:10-11)

local(本机直连)对 10.14.25.86 的**每次尝试跑满全局 3s 超时**(ReadTimeout elapsed=3000ms)——
内网目标本应走 `_forward_local_direct_http` 的快捷直连,却因不在白名单走了 `_try_http('local')`
的全局 3s 读超时路径。连续 3 次 → `circuit opened for proxy local, backoff=300.0s`。

> 注意:外部代理是"即时失败",local 是"3s 超时失败",两者失败样式不同,但都喂熔断。

### 3) 全熔断 → escape 走廊对 local 烧 3s → 刷屏 ERROR(23:07:32-44)

5 外部 + local 全熔断后,`ordered_for_domain` 返回空 → P0 逃生走廊注入 `['local']`(escape=True)。
escape 竞速 local 对 10.14.25.86 `_try_http('local')` → **又跑满 3s</think>(ReadTimeout)**
→ 竞速无 winner → `all proxies failed` ERROR + 502。每请求对 10.14.25.86 烧 3s,浏览器等 30s 断链。

**因果链可复现**(`repr_escape.py` 最小场景):全熔断后 escape 竞速 local,`_try_http('local')`
对不可达目标 7.6ms ConnectError → attempt FAILED 日志 → 竞速无 winner → 3383 ERROR。与生产日志逐行吻合。

## 结论:escape 救不了"内网目标"

P0 逃生走廊**按设计工作**(全外部熔断时强制尝试 local),但它对"local 连不上/超时"的目标仍在
**白烧 3s 超时**——它只是"最后手段的兜底",不是"内网目标的正确路径"。

**内网目标的正解是白名单强制直连**:`local_direct_domains` 命中的目标在 `_handle_http_request`
第 1.2 步就被 `_forward_local_direct_http` 拦截,本机直连:
- 不走远端代理(不触发外部代理即时失败→批量熔断连锁);
- 不被全局 3s 转发超时掐断(用 `local_direct_timeout_sec`,默认 10s);
- 失败不喂 `consec_fail`(不会因内网目标把 local 熔断)。

## 落地变更(config.yaml,gitignored)

```yaml
router:
  local_direct_domains:
    - 10.14.25.86
```

验证:Router 构造后 `_host_in_local_direct('10.14.25.86') = True`、`cn.bing.com = False`;
cli 同款 `Config(**yaml)` 加载路径解析通过,既有键(`http_read_timeout_sec` / `policies`
count=1)完好。**重启后生效**。

## 后续建议(未实施)

1. **同类内网目标一并入白名单**:正常家庭/内网环境通常还有 claude.ai 本地代理劫持、内网 NAS、
   路由器管理页等 IP 目标。若再出现某内网目标引起全站 502,先查它是否在白名单。
2. **local 反复熔断的自我恢复**:300s backoff 期间 escape 对 same 目标每请求烧 3s 仍刷屏;
   可考虑对 escape 注入的 local 也做**熔断退避期间不重复尝试**(与 `_forward_local_direct_http`
   的熔断短路同构),把刷屏带宽压下去。
3. **探针目标**:`probe_canary` 用"本机直连与上游代理均可达"的域名,内网目标不该进探针。
